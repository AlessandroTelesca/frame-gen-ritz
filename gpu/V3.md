# MotionVersion::V3: design

Status: design, written against `dev` 185fdf5. Vulkan only. Every `file:line` is at 185fdf5. Wiring facts come from the wiring map
(`.tl-scratch/i5-wiring-map.md`, cited as "map §N" and "map item N" for its closing checklist). `H` = `gpu/framegen.h`,
`C` = `gpu/framegen.cpp`, `S/` = `gpu/shaders/`.

Goal of V3: the best-looking in-between frame, at a cost of about 1.0 ms per real pair at 1080p, 2×, RX 7900 XTX (hard limit 1.1 ms).
Where V3 is unsure it smears along the motion. It never holds a patch of a real frame and never shows a sharp wrong patch.

Terms (each defined once):

| Term | Meaning |
|---|---|
| flow px | a pixel of the flow grid, `fw × fh`, `fw = rint(W / flowScale)`. 2×2 px at `flowScale` 2. |
| level | a pyramid level; level 0 = the flow grid. Vectors at level l are in level-l px. |
| F01 | full vector field on prev's grid: content at p in prev is at `p + F01(p)` in curr. Flow px. |
| F10 | full vector field on curr's grid: content at q in curr is at `q + F10(q)` in prev. Flow px. |
| level (value) | an 8-bit perceptual level, as everywhere in the library (`format.glsl`). Thresholds are in levels. |
| block | the unit of the coarse search. 4×4 level px at levels ≥ 1, 8×8 at level 0. |
| hypothesis A / B | the two ways to reach an output pixel: A via F01 (prev side), B via F10 (curr side). |
| unsure `u` | a per-pixel value in [0,1]: how little the flow can be trusted. Drives the smear. |
| occluded `o` | a per-pixel value in [0,1]: the pixel has no partner in the other frame (hidden there). |

---

## 1. Overview

V3 is a gather-based, two-flow, occlusion-aware interpolator. Per real pair the estimate measures F01 and F10 (candidate-driven
coarse-to-fine block search on a lighting-robust, colour-aware cost, then a soft per-pixel field at flow resolution), measures where
the two flows disagree (occlusion) and where a match is poor or ambiguous (unsure), and takes the pair-wide decisions (scene cut,
whole-frame fallback) on the GPU. Each synth (any t) projects both flows to time t by fixed-point gather, takes hidden content from the
one frame that shows it, blends by a replaceable weight stage, smears where unsure, clamps to the colour range of the sources and
protects static overlays. No state is kept between pairs except the existing UI-protection state.

```
ESTIMATE (once per pair; res = flow grid unless noted; (r) reads, (w) writes)
 E0  clearCounters(64) + zero state G                               u[0..63], b14.G
 E1  P_LUMA            full-res colour -> luma L0 (V1's pass)      (w) buf[0] luma level 0
 E2  P_V2_STATIC       static-structure mask S (V2's pass)         (r) buf[0]  (w) b14 S, cell maxima
 E3  CrosshairV2 luma fill (existing, if enabled)                  (w) buf[0] luma level 0
 E4  v3_planes         full-res colour -> chroma + raw planes      (r) tex, buf[0]  (w) b13 raw[0]
     v3_hist           luma histograms 3x3 tiles x 64 bins, sums   (r) buf[0]       (w) b14 G.hist, G.sum
 E5  v3_pyr (lvl 0)    high-pass features of level 0               (r) b13 raw[0]   (w) b13 feat[0]
     v3_pyr (lvl 1..n-1) 2x2 mean + features                       (r) b13 raw[l-1] (w) b13 raw[l], feat[l]
 E6  v3_search TOP     level n-1, exhaustive +-8, both dirs (z=2)  (r) b13 feat  (w) b15 BLK
 E7  for l = n-2 .. 0 (both dirs per dispatch, z = 2):
       v3_search iter 0, iter 1 (l >= 1), or one iteration (l = 0, with LK sub-pixel)
       l = n-2: v3_wide  (flagged blocks only)                      (r/w) b15 BLK
       l = LH : v3_stats (dominant motions + affine camera fit)     (r) b15 BLK   (w) b14 G.dom, G.aff
       l = 1  : probes for match ambiguity (inside iter 1)          (w) b15 BLK.amb
 E8  v3_dense          per-pixel soft field at level 0             (r) b15 BLK L0, b13 feat[0] (w) b15 FD[2], b14 MAP
 E9  v3_occl           forward-backward error, garbage measure     (r) b15 FD  (w) b14 MAP, G.unsureCount
 E10 v3_fill           colour-guided vector fill in occluded strips (r) b15 FD, b13 raw[0], b14 MAP (w) b15 FF[2]
 E11 v3_enclose        enclosure E, overlay bits C (static mask)   (r) b14 S, b15 FF (w) b14 E, C
 E12 v3_decide         scene cut, soft fallback mix, counters      (r) b14 G (w) b14 G.mode, G.failMix, u[1]

SYNTH (per t; one set per record; the blur path = the same with n samples)
 Y1  v3_project        res = flow grid, per interior sample k: fixed-point gather of both flows at t_k
                       (r) b15 FF, b14 MAP, G  (w) b15 TF[k], u[0]
 Y2  v3_synth          res = full, n samples averaged in registers: 4 taps, weight stage, smear, clamp, static mask
                       (r) tex prev/curr, b15 TF, b14 S/E/C/G  (w) out image (+ CbCr plane)
 Y3  UI patch (existing uiRecordPatch)
```
Pass counts: estimate 18 pass kinds, about 27 dispatches (n = 6 levels); synth 2 dispatches per t (`recordSynthBlur`: also 2 for any n).

Deviation from the lead's direction: the unsure/occlusion thresholds are applied in the synth (the estimate stores raw measurements), so the
tuning knobs `v3Smear`, `v3OcclSoft`, `v3Unsure` are runtime settings that act without a re-estimate (section 6).

## 2. Conventions

**Grids and units**
- All fields are in flow px. F01 on prev's grid, F10 on curr's grid, full prev↔curr displacement (not half-vectors). Pixel-centre
  coordinates: flow px `m` has centre `fs·m + (fs−1)/2` in full-resolution px (`fs` = `flowScale`).
- Full-resolution vector = `fs ×` flow vector. Positions of taps are in full-resolution px, pixel-centre coordinates, and are rounded to
  1/32 px before every colour tap (`roundEven(p·32)/32`), as every warp tap of the library is (`ui_reject.glsl` relies on it).
- Value unit: 8-bit perceptual levels (Rgba8 integer levels; Rgb10 codes/4; RgbaF16 `fgMetric`; YUV `fgLuma`, `fgYuvDiff`), identical to
  V1/V2. The colour blend stays in the source's own space (as V2: `V2_LEVELS`, `V2_TAP`, `V2_QUANT`).
- Vector storage: level-l vectors in level-l px. The camera model and dominant motions are stored in level-0 flow px and scaled by `2^-l`.

**Levels**
```
w_0 = fw, h_0 = fh;  w_{l+1} = rint(w_l / 2), h_{l+1} = rint(h_l / 2)        (same rule as V1's Level, framegen.cpp:570)
n   = smallest count with min(w_{n-1}, h_{n-1}) <= 32          (top level short side in 17..32)
BS_l = 8 for l = 0, 4 for l >= 1;   gw_l = ceil(w_l / BS_l), gh_l = ceil(h_l / BS_l)
```
At 1080p, `flowScale` 2: levels 960×540, 480×270, 240×135, 120×68, 60×34, 30×17 (n = 6); block grids 120×68 (l0), 120×68 (l1), 60×34,
30×17, 15×9, 8×5. Block (i,j) of level 1 covers exactly level-0 block (i,j): level 1→0 parents map 1:1; levels l+1→l map 2:1 (parent = block
`(i>>1, j>>1)`, "other parents" = the 3 nearest, as `search.comp` does).

`LH` (level whose results feed dominant motions and the camera fit) = `max(1, n−3)` for n ≥ 3; none for n < 3 (then candidates
5..9 are invalid). `L_wide` = `n−2` for n ≥ 4, none otherwise. At 1080p fs 2: LH = 3 (30×17 = 510 blocks per dir), L_wide = 4; dominant/camera candidates serve levels 2, 1, 0.

**Iterations per level** `nIt(l)`: top (n−1): 1 (exhaustive); n−2 .. 1: 2; level 0: 1. `fin(l) = nIt(l) − 1` is the ping-pong slot (0/1) that holds a
level's final result.

**Plane values** (flow resolution, levels)
```
Y  = (4899 R + 9617 G + 1868 B) / 16384      (luma.comp's weights; YUV: fgLuma(Y sample))
Cb = 0.564 (B - Y),  Cr = 0.713 (R - Y)      (RGB formats, R G B in levels; BT.601 chroma scaling; range about +-128)
YUV: Cb, Cr = YU_YS * (sample * YU_SCALE - 128)
```
Each plane value is the mean over the `fs×fs` cell. YUV chroma at `fs` 2: the one chroma texel of the cell; `fs` 1: bilinear chroma tap at the
pixel centre; `fs` 4: mean of the 2×2 chroma texels.

**Features** (what the search matches): for each channel c ∈ {Y, Cb, Cr}, `c_h = c − mean_5x5(c)` (box mean, clamp-to-edge). A feature
texel is 4 values `(Yh, Cbh, Crh, Y)`. High-pass features make the cost invariant to a local additive lighting offset.

**Matching cost** `C(v; Ω)` for window Ω of a block, frame roles (0,1) = (prev, curr) for F01 and (curr, prev) for F10:
```
C = (1/|Ω'|) * sum_{x in Ω'} [ 0.45 |Yh0(x) - gm Yh1(x+v)| + 0.20 |Cbh0(x) - gm Cbh1(x+v)| + 0.20 |Crh0(x) - gm Crh1(x+v)|
                               + 0.15 | Y0(x) - gm Y1(x+v) + K | ]            levels, weights sum to 1
Ω'  = window pixels whose x+v lies inside the level; if |Ω'| < |Ω|/2 the candidate is invalid (cost 255)
(gm, K) = the pair's lighting change in the frame roles of the direction, from the luma statistics of v3_hist (G.sum, G.sumSq; mu = sum / (fw fh)):
      gm = sigma_role0 / sigma_role1 (the contrast gain, clamped to [0.5, 2], 1 inside a dead band of +-0.03 so that content entering or leaving the
      frame is not read as a lighting change), K = gm mu_role1 - mu_role0. role 1 is scaled to role 0's contrast and mean, so a fade or flash (Y1 = (Y0 - K) / gm) matches
      exactly; gm = 1 gives the first draft's pure offset form, Y0 - Y1 + dMu with dMu = mu_role1 - mu_role0 (F01: mu_curr - mu_prev, F10: the negative; the first draft wrote
      "- dMu" outside the absolute value, which doubles the offset instead of removing it: fixed in step E1; the gain was added in step E2, code: `v3Term`, `v3DMu` of v3_est.glsl)
total = C + LAMBDA * |v - v_parent|_1      (all candidates except the parent's own; LAMBDA = 0.3 levels per level px)
```
Window Ω: level ≥ 1: block + 2 px apron = 8×8; level 0: 8×8 block, no apron (the dense pass finishes the job). Integer v: exact texel reads;
non-integer v (LK at level 0, dense): bilinear. Why high-pass + a small raw term: the high-pass kills fades and flashes, chroma separates
equal-luma colours, the small raw term (offset-corrected by `dMu`) stops flat regions from matching anything; flat regions tie and then the
parent/neighbour prior wins, which is right (flat areas take the motion around them).

**`.fgmaps` / `recordDebugMaps` conversion**: V1/V2 write half-vectors on the midpoint grid. V3 writes for the V1 slots: block field =
`F01 / 2` at level-0 block centres (`bw×bh`), per-pixel field = `0.5 · F01` at the pixel (not resampled to the midpoint grid; display only),
mismatch slot = zeros; header word 14 = 3. V3's real maps come from `recordDebugV3` (section 11).

## 3. Passes

Common: workgroup sizes are suggestions that the implementing step may change if it measures better. Barrier between consecutive
dependent passes: `Rec::cbar()` (map §4). Stamp names are string literals (`kMaxQ = 64`; V3 uses about 30 per pair with one synth).
"both dirs" = dispatch z = 2, z = direction (0: F01, 1: F10); the shader swaps frame roles by `dir`.

### 3.1 Reused passes (E1–E3)
- `P_LUMA` (`luma.comp`, colour variant per format, `cs.luma`): unchanged. Writes level-0 luma into `buf[0]` at `offA = 0`, `offC = fw·fh`.
- `P_V2_STATIC` (`v2_static.comp`, no per-format variant, no subgroup ops): unchanged shader. Dispatch `ceil(fw/16) × ceil(fh/16)`. V3 pushes
  `V3PC`, whose first 8 ints equal `V2PC`'s (`W,H,fw,fh,bw,bh,fscale,fIn`), `fIn = v2StaticMask ? 0 : 1`. It binds b14 (binding 14) whose layout
  contains V2B_QUAL's S region at the same offsets (section 4). Binding 13 is declared by `v2_motion.glsl` but not used by this shader.
  Runs before the CrosshairV2 fill (as V2, `C:2449-2459`), so a static crosshair is seen as static.
- CrosshairV2 `uiEstimateFill` (existing, `C:2460-2466`) rewrites level-0 luma. V3 builds Y from `buf[0]` after it, so Y sees the fill; V3's chroma does
  not (same limitation as Learned's colour planes).

### 3.2 `v3_planes.comp` (E4; per-format variant, `v3_colour_srcs`)
Dispatch `ceil(fw/8) × ceil(fh/8)`, workgroup 8×8, one flow px per thread (fs 4: the quad scheme of `luma.comp main4`).
Inputs: `texPrev/texCurr` (+ CbCr planes for YUV), `buf[0]` level-0 luma. Output: b13 `raw[0]` for prev and curr (section 4).
1. Read Y from `buf[0]` (prev at `offA`, curr at `offC`).
2. RGB formats: mean R, G, B levels over the `fs×fs` cell (format macros of `v3_format.glsl`, section 7); Cb, Cr from them with the formulas above
   and the cell's own mean Y (not `buf[0]`'s). YUV: chroma as above.
3. `raw = uvec2(packHalf2x16(Y, Cb), packHalf2x16(Cr, 0))`.
Cost budget: reads both full-resolution frames once more (the cost of `luma.comp` again).

### 3.3 `v3_hist.comp` (E4; no format variant)
Dispatch `ceil(fw/16) × ceil(fh/16)`, workgroup 256. Reads level-0 luma of `buf[0]` (prev and curr). Writes into b14 state `G`.
1. 9 tiles = 3×3 equal tiles of the frame; per frame and tile a 64-bin histogram of luma, `bin = min(63, int(Y / 4))`. Workgroup-local shared
   histogram (a workgroup lies in one tile after the tile boundaries are rounded to the 16-px grid; boundary workgroups add to their centre's tile),
   then `atomicAdd` into `G.hist[frame][tile][bin]`.
2. Sum of luma per frame into `G.sum[frame]` (`atomicAdd`, one per workgroup) in whole luma levels: the workgroup sums in 1/16 levels
   (workgroup-local, 256 px at most 1.05 M), rounds `(sum + 8) >> 4` and adds that. (The first draft said luma ×16 globally: 2.07 M flow px × 255 × 16
   overflows a 32-bit word at `flowScale` 1.) Built in step E1 together with step 1 (the tile histograms are filled from E1 on; `v3_decide` reads them in step Y2).
No other pass of the estimate depends on the histograms except `v3_decide`; `G.sum` is read by every search workgroup (`dMu`).

### 3.4 `v3_pyr.comp` (E5; no format variant)
Dispatch per level l: `ceil(w_l/16) × ceil(h_l/16)`, workgroup 16×16 (small levels: one workgroup).
- `lvl = 0` (mode bit): only the features of level 0 from `raw[0]`.
- `lvl ≥ 1`: for each pixel of a 20×20 apron tile: `raw[l] = mean of the 2×2 raw texels of raw[l−1]` (clamp at the border; odd sizes: the last row/column
  is replicated); write `raw[l]` for the inner 16×16; then `feat[l]` = raw − 5×5 box mean (from shared memory, clamp-to-edge), packed
  `uvec2(packHalf2x16(Yh, Cbh), packHalf2x16(Crh, Y))`.
Both frames in one dispatch (z = 2). 6 dispatches at n = 6. As built (E1): the box mean and the features are taken from the unquantised (float) means in shared
memory, only the stored `raw[l]` is rounded to half floats; the level-0 dispatch is `lvl = 0` with mode bit 0; no barrier is needed between the level-0 dispatch and level 1
(they write disjoint regions and read `raw[0]` only) but the code puts one between every level for simplicity.

### 3.5 `v3_search.comp` (E6/E7; no format variant)
One workgroup (64 threads) per block, both dirs (z = 2). Dispatch `gw_l × gh_l × 2`. Push: level geometry, `lvl`, `iter`, mode bits.
Window features are loaded once into shared memory (prev-role frame); the other frame is read through the cache.
Candidate evaluation: 16 candidates at once, 4 threads each (each thread sums a quarter of the window), a 4-lane sum in shared memory. A "round"
= one such evaluation of up to 16 candidates. "Ring" = the 8 integer neighbours of the round's best (one round with 8 candidates).

**TOP (l = n−1)**: seed zero; exhaustive search over all integer `v` in `[−8,8]²` (289 candidates; one thread per candidate, 64 threads loop 5 times,
each thread reading its candidate's window directly). Cost has no prior term. Writes `BLK[top][dir][0] = (v, cost, amb = 0)`. Records the second-best
cost among candidates at least 3 px from the best into `amb` (the top-level ambiguity: `amb = 1 − smoothstep(0.5, 3.0, second − best)`).

**Levels n−2 .. 1, iter 0** (candidates, 16):
| # | candidate | note |
|---|---|---|
| 0 | own parent, `2 ·` parent vector, rounded | no `LAMBDA` penalty |
| 1..3 | the 3 other nearest parents, `2 ·` vector, rounded | |
| 4 | zero | |
| 5 | camera model at the block centre, `d(x)·2^-l`, rounded | invalid if `G.aff` invalid or l ≥ LH |
| 6..9 | dominant motions D0..D3 `·2^-l` (F10: negated), rounded | invalid if unused or l ≥ LH; no `LAMBDA` penalty |
| 10 | the other direction's reverse vector: `−F_other(parent block of the parent's target)`, rounded | uses the other dir's parent-level result |
| 11..15 | unused (cost 255) | |
Then best; then a ring around the best; write `BLK[l][dir][0]`.
At level LH+1 and above, entries 5..9 are invalid (the stats exist only from LH). The wide pass (3.6) runs after L_wide's iter 1; the stats
pass (3.7) after LH's iter 1; so dominant/camera candidates serve levels l < LH, and the wide result serves everything below L_wide.

**Levels n−2 .. 1, iter 1** (reads slot 0 of the same level, both dirs): candidates: 0 own iter-0 result; 1..4 the 4 neighbours' iter-0 results
(left, right, up, down; clamp); 5 reverse vector `−F_other` at the current best's target position (bilinear in the other dir's slot 0); 6 zero;
7..9 D0..D2 (l < LH); 10 camera model (l < LH); 11..15 unused. Ring around the best. Write `BLK[l][dir][1]`. At level 1, also run the
ambiguity probes (below) on the final vector.

**Level 0** (one iteration, reads level 1 final; candidates 0..4 = own parent ×2, and the parents of left, right, up, down neighbours ×2; then the ring,
then LK):
LK sub-pixel (2 iterations): with the best integer `v`, window Ω (8×8), per window pixel the residual `r_c = f0_c(x) − f1_c(x+v)` (4 channels, weights
0.45/0.20/0.20/0.15, the Y raw term with `dMu`) and the gradient `g_c` of `f1_c` at `x+v` (central difference of the bilinear sample, ±0.5 px).
```
A = sum_x sum_c w_c g_c g_c^T + 8 I          (2x2; the 8 damps flat windows)
b = sum_x sum_c w_c g_c r_c
delta = clamp(A^-1 b, -1, 1) per axis ;  v' = v + delta
accept v' only if C(v') < C(v) (one evaluation), else stop
```
Writes `BLK[0][dir][0] = (v, cost, amb)`; `amb` is copied from the level-1 block with the same index.

**Ambiguity probes (level 1, iter 1)**: 8 probes at `v + d`, `d ∈ { ±6, ±12 } · {x, y}` level-1 px (12 to 24 flow px), fused into the ring round (As built E2 below). Per axis `a ∈ {x, y}`:
`amb_a = (1 − smoothstep(0.12, 0.40, (pmin_a − best) / max(pmin_a, 0.5))) · smoothstep(0.6, 1.4, struct_a)`, `amb = max(amb_x, amb_y)`, where `best` is the pure cost of the final
vector, `pmin_a` the pure cost of the best probe along the axis (relative: the cost excess of the probe over `max(pmin, 0.5)`; no probe, or a window not wholly inside the level: `amb_a = 0`) and
`struct_a` the window's structure along the axis (mean weighted absolute difference of neighbouring high-pass features, levels: an axis without structure says nothing). Why: a wrong-period lock
on stairs/fences has a probe whose cost is as low as the chosen one; both flows can agree on that lock, so no consistency test finds it. Stored in `BLK.amb` (and copied to level 0).

**Hook (j) `v3ColourWindow`**: before the candidates, if `mode & 1`, the window gets per-pixel weights `wgt(x) = exp(−‖(Y,Cb,Cr)0(x) − (Y,Cb,Cr)0(centre)‖₁ / 24)`
computed once from the prev-role frame's raw planes (b13 raw) and kept in shared memory; `C` becomes `Σ wgt·term / Σ wgt`. With the bit off the shader
takes the `wgt = 1` path with the same summation order and the same divisor `|Ω'|`, so the output is byte-identical to V3 without the hook. (Same weights apply to the dense pass.)

Output per block record (vec4): `(vx, vy, cost, amb)`.

**As built (E1)**
- **Two pipelines**: `v3_search.comp` (`P_V3_SEARCH`, levels n−2 … 0) and `v3_search_top.comp` (`P_V3_SEARCH_TOP`, the top level); both include `v3_search.glsl`. Reason (measured):
  the top level wants the 24×24 region of the other frame (4.6 KB, `uvec2` texels) in shared memory so that its 289 candidates run from LDS; in one shared pipeline that raised
  the shared memory of every workgroup from about 5 KB to 10 KB and slowed level 1 from 0.21 ms to 0.37 ms (workgroup occupancy on this GPU is limited by LDS). Now the main
  pipeline holds about 3.5 KB. The top pipeline uses 256 threads (candidates `tid + 256 k`, k < 2; threads 64 and up only work in that phase), 20 µs instead of 42 µs with 64 threads.
- Top: ties settle at the shorter vector (bias 0.002 level per px of `|v|_1`; the reported cost is without it); `amb` as written above (second best at Chebyshev distance ≥ 3). A
  one-level pyramid (n = 1: `min(fw, fh) ≤ 32`) has its level 0 at the top: `v3_search_top` then also runs the Lucas–Kanade refinement (8×8 block, no apron); n = 2 has no
  intermediate level (top, then level 0 reads the top's slot 0).
- Parents: the page's "level 1 → 0 maps 1:1" holds only when `ceil(w_0/8) = ceil(w_1/4)`; at odd sizes the level-0 grid can be one block wider, so every parent index is clamped
  to the parent grid (`v3BlkIdx`). The parent's result is `BLK[l+1][dir][fin(l+1)]` (`fin` = 0 for the top, 1 for levels n−2 … 1).
- Prior: every candidate except slot 0 (and the slots flagged "no prior", reserved for E2's dominant motions) costs `C + LAMBDA |v − v_0|_1`, `v_0` = the vector of slot 0
  of this iteration (iteration 1: the iteration-0 result). The stored cost is the pure `C` (capped at 255).
- Slot 10 of iteration 0: the target of the parent's vector (block centre of this block in level l+1 px plus the parent's vector) falls in other-direction block `floor(target / 4)`
  of level l+1 (slot `fin`); the candidate is `−2 ·` its vector. Slot 5 of iteration 1: bilinear (over block centres) in the other direction's slot 0 of the same level at
  the iteration-0 result's target, negated. Slots 5..9 (iteration 0) and 7..10 (iteration 1) have `cflag = 0` (cost 255) until E2 fills them.
- Rounds are branch-free (taps are always read, clamped into the level, and masked), which lets the 16 loads per thread issue together (level 1: 0.167 → 0.145 ms); the 5-value
  reductions take two barriers (8 partial sums of 8, then 8 per value) instead of a tree of 7.
- Level 0 `amb` is copied from the parent block (level 1 slot 1, or the top's slot 0 for n = 2); today that is 0 except for n = 2.
- mode bit 0 = hook (j): wired through the push constants, not read (the `wgt = 1` path is the only one); bit 1 is unused (the top level is its own pipeline).

**As built (E2)**
- Candidates (iteration 0): 5 = camera model, 6..9 = D0..D3 (negated for F10), all rounded, invalid (cost 255) when unused or l >= LH. Iteration 1: 7..10 = camera model and D0..D2. Level 0 has no stats candidates (they put lattice-quantisation
  spots into the background; measured). Dominant candidates have `cflag` bit 2 ("capped prior"): their prior is `min(LAMBDA |v - v0|_1, V3_DOMCAP = 0.5)` instead of none, so a dominant vector can win only by a real cost gain; the camera candidate keeps the normal prior.
- Gain-compensated cost (section 2): `v3Term(f0, f1, dm)` with `dm = (K, gm)` as a vec2 from `v3DMu(dir)`: `K` the brightness gain between the frames from `G_SUMSQ` / the sums, `gm` a dead band; this is what makes the fade scene pass (the LK acceptance margin tried first hurt zoom / rotate sub-pixel).
- Probes (level 1, iteration 1) are fused into the ring round (one 16-wide round: ring 8 + 8 probes at +-6 and +-12 level-1 px on both axes) instead of 12 probes at 4/8/12, which would cost a further round. Probes only count where
  the window has structure along the probe axis (per-axis structure weight) and only with fully inside windows; `amb = 1 - smoothstep(0.5, 3, minProbe/best ... )` uses the cost ratio relative to the best (relative formula) so that real footage is not ~80% ambiguous.
  Measured on battlefield pairs: share of level-0 blocks with amb > 0.5 is 3% to 9% (fast pair 100/101 7%, calm 400/401 9%, 100/104 17%).
- Level 1 costs 0.178 ms (E1 0.147): probes 0.018, the candidate setup and capped prior 0.012.

### 3.6 `v3_wide.comp` (E7 after L_wide's iter 1; no format variant) — second, much wider search (idea i)
Dispatch `gw × gh × 2` over L_wide's blocks (15×9×2 at 1080p fs 2: 270 workgroups); workgroups of unflagged blocks exit at once (no compaction needed:
the grid is tiny).
1. Flag if any: `cost > 14` levels; or the forward-backward error `e = |F01(p) + F10(p + F01(p))| > 3` level-L_wide px at the block centre (bilinear on the

2. Flagged: stage A, coarse grid `v ∈ {−24,−22,…,24}²` (625 candidates, level-L_wide px = up to ±384 flow px at 1080p fs 2), one thread per candidate
   (10 per thread), the block window (prev-role) in shared memory. Best 1 of 625 by `C` (no prior).
3. Stage B: ring ±1 around the best (8 candidates) and then ±1 once more at stride 1 around that (a 2-step refinement).
4. Replace the block's vector only if `C_new < C_old − 2.0` levels (`WIDE_MARGIN`), and write `amb = 0.5` for replaced blocks (a wide jump is a guess).
Why here: at level L_wide a block is 4×4 level px = 64 flow px; the wide search sees about ±40% of the frame width at 1080p. Cost: 270 blocks ×
(625+16) candidates × 64 px, mostly early-exit.

**As built (E2)** (differences from the text above)

### 3.7 `v3_stats.comp` (E7 after LH's iter 1; no format variant) — dominant motions and camera fit (idea h)
One workgroup (256 threads), one dispatch; all phases separated by `barrier()`. No atomics on floats: integer atomics in shared memory only.
Samples: every block of level LH in both dirs, `N_s = 2·gw_LH·gh_LH` (2 × 510 at 1080p). Sample i = `(x_i, d_i, w_i)`: for F01 at block centre `x` (level-0
flow px) with vector `v`: `d = v·2^LH`; for F10 with `f` at curr position `q`: prev position `x = q + f·2^LH`, `d = −f·2^LH` (so every sample is
"prev position → displacement to curr"). Weight `w = 1 − smoothstep(6, 18, cost)`.
Phase A, dominant motions:
1. Histogram: 32×32 bins over `[−R_H, R_H]²`, `R_H = 1.25 · 8 · 2^(n−1)` (level-0 flow px; clamp outliers to the border bin). Shared: `cnt[1024]`
   (uint, weight×16), `sx[1024]`, `sy[1024]` (int, ×16). 12 KB. Each thread loops over its samples.
2. Four times: argmax of the 3×3-smoothed counts (shared reduction); the peak vector = mean of the samples within 3×3 bins; two mean-shift iterations
   (radius 12 then 6 flow px) over all samples (shared reduction for ΣwD, Σw); store `dom[k]`; then suppress a 5×5 bin neighbourhood.
3. `dom[k]` is valid if its weight ≥ `max(8, 0.03 · Σw)`; else `domValid` bit k is 0.
Phase B, affine camera (robust, one re-weighting round):
4. Normalised coordinates `X = (x − cx) / (fw/2)`, `Y = (y − cy) / (fh/2)`. Model `d(x) = (a0 + a1 X + a2 Y,  b0 + b1 X + b2 Y)` in level-0 flow px.
5. Accumulate per thread, tree-reduce: `Σw, ΣwX, ΣwY, ΣwX², ΣwXY, ΣwY²` and the right-hand sides `Σw d, ΣwX d, ΣwY d` for dx and dy (12 values + 6).
6. Thread 0 solves the two 3×3 systems by Cramer's rule (+ `1e-3·Σw` on the diagonal).
7. Residual `r_i = |d_i − model(x_i)|`; second round: weights `w_i / (1 + (r_i/1.5·2^LH)²)`; accumulate, reduce, solve again.
8. Valid if `Σ(w_i with r_i < 2.0·2^LH) ≥ 0.4 Σw_i` and `|det| > 1e-4 · Σw³`; else `G.affValid = 0`.
**As built (E2)**: LH = max(1, n-3); the lattice is 2^LH flow px (samples are quantised to it: dominant motions are good to about 2^LH/2 px, `dom[0]` error 2..4.5 flow px in v3test, tolerance 6..11); histogram radius and the mean-shift radii (1.5 sc, 0.75 sc) scale with 2^LH; dominant mass minimum 1.5% (was 3%: a small foreground object
  must register); per-thread samples are kept in 8 registers (`cs[]`), 0.020 ms on fast pairs, 0.012 on calm. The first IRLS round of the affine fit starts from `dom[0]` as a pure translation (otherwise big shifts give inlier 0.11 and an invalid fit); the validity test counts inliers against the last round's weights.
Output: `G.dom[4]` (vec2), `G.domValid`, `G.aff[6]`, `G.affValid`, plus `G.camTrans` = `d` at the frame centre (used by the fallback mode, 3.12).
The camera candidate for F10: `−d(x)` (error of order |J|·|d|, refined away by the search).

### 3.8 `v3_dense.comp` (E8; no format variant) — the soft per-pixel field
Dispatch: tiles of 8×8 flow px offset by (−4,−4) so each tile lies between 4 block centres, `ceil((fw+4)/8) × ceil((fh+4)/8) × 2`, workgroup 64.
Reads: `BLK[0][dir][0]` (the 4 surrounding blocks), `feat[0]`, G (mode bits). Writes `FD[dir]` (vec2 per flow px) and the cost byte of `MAP[dir]`.
1. The tile's 4 block vectors `v_k`, costs `c_k`. If `max pairwise |v_a − v_b| < 0.5` flow px (uniform branch for the workgroup): every pixel
   `v = bilinear blend of the 4` (weights = bilinear position weights), cost = bilinear blend of `c_k`; return.
2. Otherwise per pixel: for each of the 4 vectors, cost over a 5×5 window of features (4 channels as in `C`, bilinear taps at sub-pixel v, `dMu` raw
   term) `c_k`. `c_min = min c_k`. Soft pick:
```
w_k = bil_k * exp( -max(0, c_k - c_min) / TAU )         TAU = 1.5 levels, bil_k = bilinear position weight of block k
v = sum w_k v_k / sum w_k ;   cost = c_min
```
3. (Inject mode, `mode & 4`, tests only) the injected vector is the only candidate; the cost is evaluated and written, nothing else changes.
Why soft: a hard per-pixel pick makes jagged edges that flicker with the block grid; a weighted blend turns a wrong pick into a small smear.
Dense window 5×5 costs 25 px × 4 bilinear taps × 4 candidates for edge pixels only (≈ 10% of pixels).
**As built (E1)**: on real footage most tiles take the soft branch (their 4 block vectors differ by ≥ 0.5 px: sub-pixel noise and real edges), not 10%; the per-pixel 5×5 windows took
0.43 ms. Now the per-vector cost is computed once per pixel of the tile and a 2 px apron (12×12 = 144 terms per vector: one feature read and one bilinear tap each) into shared
memory, and every pixel sums its 5×5 box from there (a term is −1 where the pixel or its target is outside; at least 13 valid terms, else 255): 0.087 ms. A vector within 0.25 px of an earlier
one of the tile shares its map (and so its cost). The tile (and so this branch) is uniform over the workgroup; the barrier follows it. The uniform branch
(spread < 0.5 px) is as written. Outputs: `FD[dir]`, `MAP[dir]` = `cost8` only (`e8`, `amb8`, `g8` stay 0 until `v3_occl`, step Y1), and `FF[dir]` too when mode bit 1 is set
(E1 set it: `FF = FD` until `v3_fill` existed; step Y1 clears the bit, `v3_fill` writes `FF`). Inject mode: per pixel (the injected vector differs per pixel, so no shared map),
`FD` is read, nothing but the `cost8` of `MAP` is written; `FF` stays the copy of the injected flows that `recordEstimate` made.

### 3.9 `v3_occl.comp` (E9; no format variant) — consistency, garbage measure
Dispatch `ceil(fw/16) × ceil(fh/16) × 2`, workgroup 16×16, shared tile with a 4 px apron (for the 9×9 box). Per pixel p of dir (F01 shown, F10 symmetric):
1. `e = |F01(p) + F10(p + F01(p))|` (bilinear sample of FD of the other dir, flow px). If `p + F01(p)` is outside the frame: `e = 31.9`.
2. `tol = 0.6 + 0.02 |F01(p)|`; occlusion ramp with the estimate defaults `o = smoothstep(1.0, 2.5, e / tol)`.
3. `oBox` = mean of `o` over the 9×9 window (shared memory). `g = smoothstep(0.35, 0.70, oBox)` ("garbage": a broad inconsistent region is not an occlusion strip).
4. Write the MAP word (section 4): `cost8` is kept; set `e8 = min(255, 8e)`, `g8 = round(255 g)`; `amb8` from the L0 `BLK.amb` (bilinear on the block grid).
5. Count (workgroup-local, then one `atomicAdd` per workgroup into `G.unsureCount`): pixels with `u ≥ 0.5` where `u` is section 3.11's formula with
   the setting defaults, and `G.costSum += cost` (fixed point ×16).
Why `e` is stored raw: the synth applies the ramp with `v3OcclSoft` and `v3Unsure`, so they are runtime knobs.

**As built (Y1)**
- The garbage measure needed a second condition. With `g = smoothstep(0.35, 0.70, oBox)` alone, every occlusion strip wider than the 9×9 window (about 9 flow px: any strip at a layer speed
  difference above 10 px per pair) is "a broad inconsistent region": `g` goes to 1, `o_eff = o (1 − g)` to 0 and `u` to 1 inside the strip, so the one-sided weights never act and the
  strip is a smeared two-frame blend (`layers` with exact flows: error inside the hidden strips 5.5–7.5 levels, a plain blend 16–19). Now `g = smoothstep(0.35, 0.70, oBox) · smoothstep(1.0, 3.0, spread)`,
  with `spread` = the standard deviation (flow px) of the vectors of the occluded pixels of the window, weighted by `o` (`Σ o v² / Σ o − |Σ o v / Σ o|²`): a strip, however wide, has the coherent vectors of the surface that is revealed
  or covered; random vectors (garbage) do not. Inside the strips the error with exact flows is now 0.2–0.7 levels (see the test table in section 12 / Y1). Cost: on pairs with broad but
  coherent inconsistent regions (wrong flows that agree with their neighbours) the pixels now count as occluded instead of garbage.
- Box sums: separable (a 24×24 tile of `(o, o v, o |v|²)` as vec4, horizontal 9-sums, vertical 9-sums); the window mean divides by the in-frame pixel count. 0.043 ms (the straight 81-tap loop: 0.068).
- The `MAP` word is written whole (`cost8` kept). `o_eff` with the estimate's defaults is also stored as a float in V3B_AUX words `[2N + dir N + pix]` (the words `[2N, 4N)`, free in the layout), for `v3_fill`'s walks.
- `G.costSum` is `Σ cost8 · 2` (the ×16 fixed point of `cost`), `G.unsureCount` counts the pixels of both grids with `u ≥ 0.5` computed from the stored (quantised) values. `amb` is 0 in inject mode (mode bit 2: the block records are stale).

### 3.10 `v3_fill.comp` (E10; no format variant) — vectors in occluded strips
Dispatch like `v3_occl`, both dirs. Reads `FD`, raw colour (the pixel's own frame: prev for F01, curr for F10) from b13 `raw[0]`, `MAP`.
Writes `FF[dir]`. A pixel with `o_est < 0.2` copies `FD`. Otherwise (≈ 3–8% of pixels):
1. In each of the 4 axis directions walk up to `R_FILL = 12` flow px to the first pixel with `o_est < 0.1`; take its vector `v_k` and colour `col_k`, distance `d_k`.
2. `w_k = exp(−‖col(p) − col_k‖₁ / 24) / (1 + d_k / 8)`; `v_fill = Σ w_k v_k / Σ w_k` (none found: keep `FD`).
3. `FF = mix(FD, v_fill, smoothstep(0.2, 0.8, o_est))`.
Why colour-guided: the vector of an occluded pixel is garbage (it has no partner); the revealed/covered surface is the one it looks like, and
similar colour in its own frame picks the side it belongs to without depth. (This is the same idea as the (j) switch, and uses the same weight formula.)

**As built (Y1)**: the walks use `o_est = o_eff = o (1 − g)` (3.9, from the float map `v3_occl` wrote), not the raw `o`: in a garbage region there is no trustworthy neighbour within reach and the pixel is smeared by `u` instead. The four walks advance in
lock-step (independent loads overlap): 0.036 ms on a fast pair (a walk per flagged pixel, 4 × 12 loads at most; a pixel is flagged at `o_est ≥ 0.2`, more pixels than the page's 3–8% on fast pans). Dense mode bit 1 (FF = FD) is no longer set.

### 3.11 The unsure measure `u` (computed in `v3_project` and, with defaults, in `v3_occl`)
Inputs per pixel: `cost` (levels), `e` (flow px), `amb`, `g`. With knobs `κ = v3Unsure`, `σo = v3OcclSoft`, `F` = the pixel's vector length:
```
tol    = 0.6 + 0.02 F
o      = smoothstep(1.0, 1.0 + 1.5 σo, e / tol)
o_eff  = o * (1 - g)
ucost  = smoothstep(6 κ, 18 κ, cost)
u      = max( ucost * (1 - o_eff),  0.8 * amb,  0.25 * o_eff,  g )
```
Meaning: a poor match unexplained by occlusion is unsure; an ambiguous match is unsure; occluded pixels get a little smear (their filled vector is a
guess); a region that is mostly inconsistent is unsure outright.

**As built (Y1)**: code `v3_maps.glsl` (`v3Occ`, `v3OccEff`, `v3UnsureOf`, the MAP unpacking): `g` is the stored garbage measure (3.9 as built). `v3_project` applies the runtime knobs (`v3OcclSoft` in `v3Occ`, `v3Unsure` in `v3UnsureOf`) to the stored `cost`, `e`, `amb`, `g`.

### 3.12 `v3_decide.comp` (E12; no format variant) — one decision per pair
One workgroup of 64 threads. Reads `G.hist`, `G.unsureCount`, `G.costSum`, settings from push.
1. Scene cut: for each of the 9 tiles, `p_b = (h0_b + 1) / (N_t + 64)`, `q_b` likewise from frame 1; `D_t = Σ_b (p_b − q_b) ln(p_b / q_b)` (symmetric KL);
   `D = mean_t D_t`; `cut = v3SceneCut > 0 && D > v3SceneCut` (default 0.45; FSR 3's tile layout and threshold).
2. `share = G.unsureCount / (2 · fw · fh)`. `G.failMix = smoothstep(globalFallback, 1.5 · globalFallback, share)` (a float in [0,1], one value per pair, shared by every synth of the pair).
   Why soft (lead's amendment A1): with no state between pairs there is no hysteresis, so a binary switch on a share that hovers around the threshold would flip the whole frame between the
   estimated flows and the camera-model field from one pair to the next, and show as flicker. A ramp turns that into a gradual change.
3. `G.mode = cut ? 1 : 0` (0 normal, 1 scene cut, binary by nature). The fallback is `G.failMix`, not a mode.
4. Counters, in the existing conventions (`bench/score` reads them through `recordDebugCounters`, `u[0]`, `u[1]`):
   `u[1] = cut ? 255·256·Nb : round(256 · meanCost · Nb)` where `Nb = bw·bh` (`debugSadBlocks`, level-0 blocks of 8×8, equal to V1's) and `meanCost` is the mean of
   `G.costSum` over flow px (levels); so `u[1]/256/Nb > 30` ("cut%") holds exactly when the scene cut fired. `G.unsureCopy = G.unsureCount / 2 · fs²` is the
   untrusted-pixel figure; `v3_project` (thread 0, workgroup 0) writes `u[0] = G.unsureCopy` because every synth zeroes `u[0]` (`clearCounters(1)`).
   When `failMix = 1`, `u[0]` is reported as `W·H`; otherwise as the unsure count (as above). (`fallback%` > 15% then holds when `failMix` is 1 or the unsure share is large.)

Whole-frame outputs of the decision (all uniform over the frame; none is local):
- `mode 1` (scene cut): `v3_synth` writes the nearer real frame (prev for t ≤ 0.5, curr after), as V1/V2/FSR do. Deviation from the lead's note (a blend):
  a cross-fade of two unrelated scenes is a ghost frame; at a cut the nearer real frame is what the content actually does and holds nothing back.
- `failMix` (estimate failed, soft; replaces the former binary mode 2): the camera-model field is `G.aff` if valid; else the first valid dominant motion; else zero. `v3_project` blends toward it
  by `failMix` (3.14): the vectors become `mix(estimated, camera model, failMix)`, `u = max(u, failMix)`, `o` and `hole` are multiplied by `1 − failMix`. At `failMix = 1` the synth shows a
  time-weighted blend of both frames smeared along the camera motion; between 0 and 1 it is a mixture, so a pair whose share hovers around the threshold changes gradually.

**As built (Y2)**: `v3_decide.comp` as above (one workgroup of 64) with these differences:
- Histogram distance: `D = min(D_raw, D_comp)`: `D_comp` is the same symmetric KL after mapping frame 1's bins through the pair's lighting model (`v3DMu(0)` = `(K, gm)` of `v3_est.glsl`, `y0 = gm·y1 − K`; bin mass is split linearly over the two target bins). Without it the `fade` scene (colour `T (1 − 0.35 τ) + 12 τ`) reads as a cut (`D` = 4.9); with it `D` = 0.054, while a real cut stays above the threshold (synthetic cut `D` = 13.5; two unrelated real clips, see the report). A cut between two scenes with the same level statistics (the same generator with another seed, an inverted noise picture) is not visible to a histogram (`D` 0.23–0.25): that is the user's choice of method, not a defect of the pass.
- The failed-estimate share counts **only the pixels that could have found a partner and only the clearly unsure ones**. `v3_occl` adds two counters to `G` (words 30 `G_ELIG`, 31 `G_UNSURE_ELIG`, and word 29 `G_HIST_D` is the histogram distance for the debug header): eligible = own vector target and camera-model target both inside the frame (`camModel` is moved into `v3_maps.glsl` for it); unsure for this counter = `u ≥ 0.9` (the `unsureCount` / `u[0]` figure stays at `u ≥ 0.5`). `share = G_UNSURE_ELIG / max(G_ELIG, 0.25 · 2 fw fh)`; `failMix = smoothstep(globalFallback, 1.5 globalFallback, share)`. Why: (a) a 350–500 px pan has 25–40% of its pixels unmatched because their content leaves the frame, and the estimate is good (`shift (350,−300)` error 1.6 vs the 2.0 limit; with the plain share `failMix` was 1 and the error 11); (b) on real footage the `u ≥ 0.5` share is 18–47% on correct estimates (compressed, noisy, motion-blurred content: matching cost above 10 levels is common), which turned the fallback on for every pair and cost 3 dB on calm pairs; with `u ≥ 0.9` on eligible pixels the shares are 6–18% on the 2-frame pairs (`failMix` 0 on bf100 / bf400 / mc05 / mc06, 0.12 bf900, 0.14 cs2a, 0.36 cs2b) and 20–28% on the 4-frame pairs (`failMix` 0.72 bf100x4, 1.0 bf400x4). A fast, noisy pair can still be flagged (`mc06` frames 500/502, rain: `failMix` 1.00): the threshold is a calibration point for step F.
- `G.mode` is 0 or 1 only. `G_UNSURE_COPY = W·H` on a cut or when `failMix ≥ 1`, else `unsureCount / 2 · fs²`. `u[1] = 255·256·Nb` on a cut, else `round(256 · meanCost · Nb)`.
### 3.13 `v3_enclose.comp` (E11; no format variant, no subgroup operations)
Dispatch `ceil(N8/64)` workgroups of 64 threads, one cell (8×8 flow px) per thread; `N8 = s8W·s8H`. Replaces `v2_enclose.comp` (which needs subgroup
shuffles and ≥ 16 lanes: V3 avoids that requirement). Same output semantics and same b14 offsets (`eOff()`, `cOff()` of `v2_motion.glsl`):
1. `E` = min over the 4 axis directions of the max of `s8` over steps 1..6 cells (`E_R = 6`); `E` is non-zero only when all four sides have structure.
2. `near` = `E > 0` or any of the 3×3 cells' `s8 > 0`.
3. `tap` bit: the segment `m − v … m + v` (`v` = `FF[0]` at the cell's centre pixel, in cells = `v/8`; full vector, since taps of a pixel at any t lie on it),
   walked in steps of ≤ 2 cells, with a 3×3 box of cells around each step, any `s8 > 0`.
4. `qb[eOff()+c] = floatBitsToUint(E)`, `qb[cOff()+c] = near | (tap << 1)`.
Cost 32k threads × ~60 reads, no shared memory.

**As built (Y2)**: as written, with the 3×3 cell box also used for the `near` bit (page: 3×3 cells; kept) and the tap segment walked at the cell centre with a cap of 48 steps. Output words `E` and `C` at the b14 offsets (`eOff()`, `cOff()`); V3 owns `P_V2_STATIC` in its pipeline group (`recordEstimate` runs it right after luma with `V3PC`, whose first 8 ints equal `V2PC`'s, so V2's SPIR-V is reused unchanged; `Settings::v2StaticMask` = false switches the mask off for V3 too: `fIn` = 1). Cost 0.006–0.011 ms (`enclose`), `static` 0.0085 ms.

### 3.14 `v3_project.comp` (Y1; no format variant) — flow projection by gather, per t
Dispatch `ceil(fw/8) × ceil(fh/8) × nInt` (z = interior sample), workgroup 8×8, one output position `m` (flow px) per thread. Reads `FF[0..1]`, `MAP[0..1]`,
`G`. Writes `TF[k]` (slot k of the T-field, 4 words per flow px, section 4). `t = t_k`.
Hypothesis A (prev side): `p ← m`; twice: `p ← m − t · F01'(p)` (bilinear `FF[0]`; start from `p = m − t F01'(m)`). Then `gA = F01'(p)`,
residual `rA = |p + t gA − m|` (flow px), `holeA = smoothstep(0.75, 2.0, rA)` (nothing from prev lands here: a hole). Maps at the nearest
flow px to `p`: `cost, e, amb, g` → `oA`, `uA` (section 3.11). Hypothesis B (curr side): `q ← m − (1−t) F10'(q)` (twice), `gB = F10'(q)`, `rB = |q + (1−t) gB − m|`,
`holeB`, `oB`, `uB` likewise.
Mode 1: nothing written (the synth copies a real frame). Fallback: `f = G.failMix` as below (at `f = 1`: `gA = gB = camera model(m)`, `oA = oB = 0`, `hole = 0`, `uA = uB = 1`).
Packed record (4 words): `w0 = packHalf2x16(gA)`, `w1 = packHalf2x16(gB)`, `w2 = pack4x8(oA, holeA, uA, 0)`, `w3 = pack4x8(oB, holeB, uB, 0)` (unorm 8 bit).
The vectors are half floats (precision 0.06 flow px at 100; sub-frame blur at that size hides it).
Why a flow-resolution pass: the fixed point (2 iterations × bilinear × 2 flows) is done once per flow px instead of once per output px (4× fewer
threads at `flowScale` 2, 16× at 4); the full-resolution pass reads 4 neighbours of `TF` bilinearly.
Fallback (soft, `f = G.failMix`): the camera-model vector `gc(m)` (`F10`: negated) is computed per flow px; for both hypotheses `g = mix(g_estimated, gc, f)`; `u = max(u, f)`, `o = o · (1 − f)`, `hole = hole · (1 − f)`.
Thread 0 of workgroup (0,0,0): `u[0] = G.unsureCopy` (`f = 1`: `W·H`).

**As built (Y1)**
- Fixed point: start `p = m − t F01'(m)`, then **two** more iterations (the text above counts the start as one: three evaluations of `F01'`). `oA/oB` stored are `o_eff` (3.9 as built) computed with `v3OcclSoft`; `uA/uB` with `v3Unsure`.
- The sample times come from the host: `v3Synth` computes `t_k = clamp(t0 + (t1 − t0)(k + 0.5)/n, t0, t1)` in double (as `recordSynthBlur` does) and writes them as floats into `G` words `G_TK = 1200 ..` (`CmdUpdateBuffer`, up to 16); `v3_project` and
  `v3_synth` read them. A float formula in the shaders differs from the host's in the last bit, which rounds a tap position (1/32 px) differently at exact ties (N = 3: `t = 1/6`) and made the blur test's "sub-frame == recordSynth(t_k)" fail by 2 levels in 0.001% of the bytes.
- Dispatch z = the interior sample count `nInt`; `V3PC.iter` = the first interior sample index `lo`, `V3PC.lvl` = `nInt` (`v3_synth` reads `TF` slot `k − lo`). `nInt = 0` (every sample a real frame): no project pass.
- `G.mode == 1` returns before writing (the synth does not read `TF` then, Y2). `G.failMix` and the camera model (`G.aff`, else the first valid dominant motion, else 0) are wired as written (F10: `−d(m − d(m))`); until `v3_decide` (Y2) `failMix = 0` and the branch is not taken (it is uniform over the dispatch).
- `u[0]` is written by thread (0,0,0) of slot 0 (`G.unsureCopy`, which is 0 until `v3_decide` exists; `W·H` at `failMix = 1`).
- `V3PC.fdOff` (replaces `pad[0]`): the word offset of `FD` in `V3B_FLOW` (= `16 B`); `FF` = `fdOff + 4N`, `TF` = `fdOff + 8N`, slot `k` at `+ 4 N k`.
- `TF` growth: `v3Synth` grows `V3B_FLOW` when `nInt` exceeds the slots held (`v3Ns`): a new, larger buffer, a `vkCmdCopyBuffer` of the whole old one (BLK, FD, FF, TF: the estimate survives) at the start of the record, the old one into `blurGrave` (freed with the rest at resize / destroy); the bytes are checked against `maxStorageBufferRange`; failure returns false.
  `takeSet` is called after the growth (it binds the buffer current then). Blur at 1080p `flowScale` 2: 8.3 MB per slot.

### 3.15 `v3_synth.comp` (Y2; per-format variant, `v3_colour_srcs`) — occlusion-aware synthesis
Dispatch `ceil(W/8) × ceil(H/8)`, workgroup 8×8, one output pixel per thread, all n samples in registers (n = 1 for `recordSynth`). Includes `v3_weights.glsl`
(section 3.16). For each interior sample k (sample times `t_k = t0 + (t1 − t0)(k + 0.5)/n`, as `recordSynthBlur`; samples with `t_k ≤ 0` / `≥ 1` = the real frame prev / curr):
1. `G.mode == 1`: output = prev (t ≤ 0.5) or curr; write; skip the rest.
2. Static mask: `bits = sCellBits(sCell(x))`; if bit 0 set, `sAt(x)` gives `(Sn, E, Sd)`; `σ = max(Sd·conf, E·(1 − fit))` (below).
3. Read `TF[k]` at the 4 flow px around `x` (bilinear): `gA, gB` (px = `fs ·`), scalars from the nearest flow px: `oA, holeA, uA, oB, holeB, uB`.
4. Taps (positions rounded to 1/32 px; raw working values `V2_LEVELS`-style; CrosshairV2 rejection `uiReject(V3_UIP(pa), V3_UIP(pc_), wa, wc)` on each
   raw tap pair, `uiRejectC` for YUV chroma):
   - A: `CAp = prev(x − t gA)`, `CAc = curr(x + (1−t) gA)`;  B: `CBc = curr(x − (1−t) gB)`, `CBp = prev(x + t gB)`;
   - a tap outside the frame takes its partner (soft over 2 px past the edge: `outside()` of `v2_morph.glsl`).
5. Weight stage (3.16): inputs `CAp, CAc, CBp, CBc, oA, holeA, uA, oB, holeB, uB, t` → weights `w[4]` (sum 1) and smear `s`.
6. Sharp colour `Cs = w0 CAp + w1 CAc + w2 CBp + w3 CBc`.
7. Pixel clamp (k): per channel `lo, hi` = min / max over the 3×3 texels around each of the two taps of the **dominant** hypothesis (the one with the larger
   `w0+w1` vs `w2+w3`), plus, when the weights are within 0.25 of each other, over the other hypothesis' two 3×3 as well. `Cs = clamp(Cs, lo, hi)`.
   YUV: Y 3×3 texels, chroma 3×3 chroma texels. ≈ 18–36 texel reads (the cost line "clamp" in the budget).
8. Smear (e): if `s > 1/16`: for `j ∈ {−2…2}`, `τ_j = j · (v3Smear · s / 2)`, `|τ_j g| ≤ 48 px`: the whole tap set (all 4 taps) is re-sampled at
   `time t + τ_j` of its own hypothesis (positions `x − (t+τ_j) g`, `x + (1−t−τ_j) g`), weights `w` as in 5. Smeared colour `Cm = Σ_j k_j C_j`, `k = (1,2,3,2,1)/9`.
   Output `C = mix(Cs, Cm, smoothstep(0.05, 0.5, s))`. (A smear sample is a convex mix of real source pixels, so it needs no clamp; it is not clamped.)
9. Static: `Cz = (1−t) prev(x) + t curr(x)`; the static weight `ws = σ`; `C = mix(C, Cz, ws)`. `fit` (how clearly the moving hypotheses fit better than the zero
   vector) = `smoothstep(0, 12, dz − dm)` with `dz` = `max_ch |prev(x) − curr(x)|`, `dm` = the dominant hypothesis' pair disagreement (levels).
   `conf` = `tapsStatic`-style agreement (`1 − dz / 12`, clamped) so a moving texture that matches S's structure is not frozen.
10. Quantise exactly as the store does (`V2_QUANT`-equivalent, `v3_format.glsl`); accumulate with the blur weights (`mode & 1`: Gaussian `exp(−2 x²)`, `x = (2k+1−n)/n`; else even).
11. Store: `FG_STORE` / YUV `fgOut`; YUV: the CbCr plane is written once per 2×2 block by the even-even pixel from that pixel's chroma (chroma of the 2×2 block centre
    tap, as `V2_TAP`/`tapYuv` do), exactly as `resolve.comp` / `v2_morph.glsl`.
`mode & 2`: hook (l) `v3DetailSplit` (3.16). `mode & 8`: debug dump (3.16).
The UI patch (`uiRecordPatch`) runs after this pass.

**As built (Y1)**: steps 3–6, 10, 11 only; the Y2 places are marked `Y2:` in `v3_synth.comp` (step 1 `G.mode == 1`, step 2 static mask, the `uiReject` on each raw tap pair, steps 7, 8, 9; the debug dump). Details:
- `TF`: `gA, gB` bilinear over the 4 flow px around `x` (`fp = (x − (fs − 1)/2) / fs`), **and the scalars `(o, hole, u)` of both hypotheses bilinear too** (the page says "nearest"; a step at the flow grid is a hard edge of 2 px at `flowScale` 2 in the one-sided weight, measured on `layers`: o_eff ramps of 1–5 flow px
  with single steps of up to 0.7; the bilinear read costs 8 more words per pixel).
- Taps through `V3_TAP` (1/32 px); `edgeReject` (the page's "a tap outside the frame takes its partner", `outside()` of `v2_morph.glsl`) on each pair of taps before the weight stage. `alpha = mix(prev.a, curr.a, t)` at the pixel itself.
- `V3_QUANT(Cs)` per sample, averaged with the blur weights, stored once. No smear: `wo.s` is computed and ignored. No zero-vector re-tap for holes (see 3.16).
- Cost: 0.037 ms at 1080p `flowScale` 2 for one `t` (design 0.265 for the finished pass: no clamp, smear or static yet).

**As built (Y2)**: steps 1–11 all present (`v3_synth.comp`, `v3_static.glsl` for the static helpers `sReject`, `tapsStatic`, `v3StaticWeight`). Differences and details:
- The synth pulls the static pixels to the zero-vector blend with V2's own decision logic ported (`v2_morph.glsl`'s `V2_Z0/Z1/ZMAX`, `SEPS/SR/SD` constants live in `v3_static.glsl`): `σ` from the structure map and the pair disagreement `dz − dm`; `sReject` (near overlays only, `C` bit 0/1) rejects a tap that lands on a static structure's pixels.
- `uiReject` is applied to each raw tap pair before `edgeReject` and `sReject` (`v3Pair`).
- Clamp (step 7): the 3×3 ranges of the dominant hypothesis' two taps (both hypotheses when `|wA − wB| < 0.25`), through `v3Box(bool onCurr, pos, lo, hi)`. Alone it costs 0.026 ms in the synth pass (0.150 → 0.123 ms, `fgtest --bench`, 1080p fs 2).
- Smear (step 8): the 5-tap kernel `(1,2,3,2,1)/9`, `τ_j = j · v3Smear · s / 2`, each sample re-taps all four taps of both hypotheses at `t + τ_j` of their own hypothesis (capped so that `|τ_j g| ≤ 48 px`). Unsure pixels get their colour from the pair's own flow vectors (the hypotheses' real source pixels sampled along the motion line at several times and averaged) and never from a local copy of the neighbourhood. Skipped entirely (`if`) when `v3Smear = 0` or `s ≤ 1/16`; the output with `v3Smear = 0` is byte-identical to a build with the smear stage compiled out (cmp on two real pairs). Hidden strips with exact flows rise from 0.24–0.66 to 0.67–1.02 mean error: `s ≥ 0.25 · o_eff` smears occluded pixels, that is the price of the smear along the motion where the one-sided weight is ramping.
- Cut (mode 1): the synth writes prev for `t ≤ 0.5`, else curr (before any tap work).
- Debug dump (`mode & 8`): `pc.lw` = pixel stride, `pc.lh` = record count; the record (28 floats, section 3.16) is written into **a slot of the flow-resolution T-field buffer** (`V3B_FLOW`, offset `fdOff + 8N + lvl · 4N`, slot count grown on demand), not into a new binding: no descriptor binding is free and a record per pixel does not fit the interior samples' budget at full resolution, so `recordDebugV3Weights` takes `maxPixels` (default 65536) and dumps every `stride`-th pixel of the raster (stride = ceil(P/want)), then copies slot 1 to the caller buffer (compute → transfer barrier). `debugV3WeightsLayout(maxPixels, DebugV3Weights&)` returns count, stride and size. Hook bits: `mode & 2` (`v3DetailSplit`) is read by nothing (a no-op); `v3ColourWindow` reaches `v3_dense` as before (no-op).
- Sample times `t_k` from `G` words 1200.. (Y1); the blur path and `recordSynth` are the same code (`blurtest check --algo v3` passes).

### 3.16 `v3_weights.glsl` — the replaceable blend-weight stage
One include, one function, no side effects, no access to buffers except through its arguments:
```glsl
void v3Weights(in V3WIn i, out V3WOut o);
```
| Direction | Field | Type | Meaning / units |
|---|---|---|---|
| in | `CAp, CAc` | vec3 | hypothesis A's prev / curr sample, working values (levels; F16: raw, YUV: Y,Cb,Cr levels) |
| in | `CBp, CBc` | vec3 | hypothesis B's prev / curr sample |
| in | `oA, oB` | float | occlusion in [0,1]: the partner of A's prev pixel is hidden in curr / B's curr pixel hidden in prev |
| in | `holeA, holeB` | float | [0,1]: nothing lands at this output pixel via that hypothesis |
| in | `uA, uB` | float | unsure in [0,1] |
| in | `t` | float | sample time in (0,1) |
| in | `lenA, lenB` | float | hypothesis vector length, px |
| in | `D(.,.)` | function | `V3_D(a, b)`: per-channel distance in levels (format macro) |
| out | `w[4]` | float | weights for `CAp, CAc, CBp, CBc`; sum 1; ≥ 0 |
| out | `s` | float | smear amount in [0,1] |
Classical implementation:
```
wAc = t (1 - oA);   wAp = 1 - wAc            // hidden in curr -> prev only; hidden in prev would be oB
wBp = (1-t) (1 - oB);  wBc = 1 - wBp          // B owns curr: hidden in prev -> curr only
dA = max_ch D(CAp, CAc);  dB = max_ch D(CBp, CBc)
sA = mix(1 - smoothstep(12, 40, dA), 1, oA)   // pair agreement; ignored where the partner is hidden
sB = mix(1 - smoothstep(12, 40, dB), 1, oB)
HA = (1 - holeA) (1 - 0.5 uA) (0.25 + 0.75 sA);   HB = (1 - holeB) (1 - 0.5 uB) (0.25 + 0.75 sB)
if (HA + HB < 1e-3): both holes -> HA = HB = 0.5, wAp = wBp = 1-t, wAc = wBc = t, hole = 1 (taps at x with the zero vector in the caller)
wA = HA / (HA + HB);  wB = 1 - wA
w = (wA wAp, wA wAc, wB wBp, wB wBc)
s = max( wA uA + wB uB,  hole )
```
Two layers through the same x: both hypotheses are valid and disagree; the one whose own two samples agree wins softly, equal → average (no hard edge).
Occluded/hole pixels never change the smear to a hold: the weights can only move toward one real frame's *warped* tap.
**Hook (l) `v3DetailSplit`** (`mode & 2`, default off): in `v3_synth.comp` step 6, `Cs = Σ w_i lowpass(C_i) + detail`, where `lowpass(C_i)` = the 3×3 mean of the clamp fetches
of step 7 for that source and `detail = C_dom − lowpass(C_dom)` of the single source with the largest weight. Off: step 6 as written; the extra code is in a branch
that is not taken, and the clamp fetches are the same, so the off output is identical.
**Debug dump** (`mode & 8`, through `recordDebugV3Weights`, section 11): per output pixel, 28 floats to a caller buffer: `CAp CAc CBp CBc` (12), `oA holeA uA oB holeB uB t lenA lenB σ`
(10), outputs `w0..w3 s` (5), 1 pad. This is exactly the net's input and target record; a later net replaces `v3Weights` (or a separate pass fed from this record) and nothing else.

**As built (Y1)**: `v3_weights.glsl` as written, with one change: the page's special case `HA + HB < 1e-3` (both holes) is replaced by the continuous form `wA = (HA + 1e-4) / (HA + HB + 2e-4)` (the ratio tends to 1/2 when both vanish: a time blend of the
taps) and `hole = 1 − smoothstep(0, 0.02, HA + HB)` in `s`; no zero-vector re-tap (the caller is unchanged: the taps are the hypotheses' own). The record `V3WIn` / `V3WOut` structs are in the include.
`recordDebugV3Weights` stays a stub (returns false): the dump needs a caller buffer on a descriptor binding and no V3 binding is free (13–15 are the three V3 buffers, 0–12 the shared set); step Y2 can bind it, or write the record into a `TF` slot beyond `ns` (a window of at most `4N/28` pixels).
`v3test --profile` prints the occlusion ramp along the middle row from the dump instead.

## 4. Buffers and images

N = `fw·fh`; P = Σ_l `w_l h_l` (≈ 4N/3); B = Σ_l `gw_l gh_l`; `N8 = ceil(fw/8)·ceil(fh/8)`; `ns` = interior samples held (1; grown by the first blurred record, only grows).
V3 owns three buffers in its `MotionGroup::bufs` (`V3B_PYR, V3B_AUX, V3B_FLOW`, created by `motionSized`, `C:1683-1694`, destroyed by `destroySizeDependent`), bound to the

|---|---|---|---|---|---|

## 5. Push-constant block `V3PC` (128 bytes)

Pushed over the same 128-byte range as `PC`/`V2PC` (`VkPushConstantRange{COMPUTE,0,sizeof(PC)}`, `C:1330`); `static_assert(sizeof(V3PC) == sizeof(PC))`;
the same block in `v3_common.glsl`. The first 8 ints are identical to `V2PC` so `v2_static.comp` can be pushed with it.
```cpp
struct V3PC {
    int W, H, fw, fh, bw, bh, fscale, fIn;   // 32 B: V2PC's prefix. bw,bh = level-0 block grid (8x8). fIn = 1: Settings::v2StaticMask off
    int lw, lh, gw, gh;                      // 16 B: this pass's level size and block grid; synth/others: unused
    int lvl, iter;                           // 8 B: level, iteration; synth: lvl = interior sample count nInt, iter = first interior sample index
    int mode, n;                             // 8 B: mode bits (below); n = samples of this output (1 = recordSynth)
    float t0, t1;                            // 8 B: sample window; recordSynth: t0 = t1 = t
    float cutThresh, globalFrac;             // 8 B: Settings::v3SceneCut, Settings::globalFallback
    float smear, occlSoft, unsure;           // 12 B: v3Smear, v3OcclSoft, v3Unsure
    float cx, cy;                            // 8 B: model centre x, y (fw/2, fh/2) (stats), spare otherwise
    int fdOff;                               // 4 B (Y1): word offset of FD in V3B_FLOW (16 B); FF = fdOff + 4 N, TF = fdOff + 8 N
    float pad[6];                            // 24 B (the fields above are 104 B; the first draft's pad[2] made 108 B, not 128: fixed in step S)
};                                           // = 128 B
```
`mode` bits, per pass: search: bit 0 = hook (j) colour window; dense: bit 0 = (j), bit 1 = also write `FF` (= `FD`; until `v3_fill`), bit 2 = inject (tests); synth: bit 0 = Gaussian blur weights, bit 1 = hook (l) detail split,
bit 3 = debug dump; occl (Y1): bit 2 = inject (amb = 0). Passes never read each other's meaning of a bit.
`W,H,fw,…` come from `Rec::Rec` (`C:2000-2010`) as for V2, with a `v3pc()` next to `v2pc()` (`C:2042-2050`).

## 9. Reach

Guaranteed reach of the top-level search plus the local refinements, in flow px, full prev→curr vector:
```
top_reach(l=n-1) = R_TOP * 2^(n-1)              = 8 * 2^(n-1)
refinement slack = sum_{l=0}^{n-2} (ring 1 + 1 pass at 2 levels each) * 2^l  ~ 2 (2^(n-1) - 1)
reach_px        = top_reach * flowScale  (guaranteed, top level alone);   wide search on flagged blocks: 24 * 2^(n-2) * flowScale
```
| Frame | `flowScale` | n | top reach (flow px) | **guaranteed** (px, top level alone) | with refinement (px) | wide, flagged blocks (px) |
|---|---|---|---|---|---|---|
| 1080p | 2 | 6 | 256 | **512** | 636 | 768 |
| 1080p | 1 | 7 | 512 | 512 | 636 | 768 |
| 1080p | 4 | 5 | 128 | 512 | 636 | 768 |
| 1440p | 2 | 6 | 256 | 512 | 636 | 768 |
| 4K | 2 | 7 | 512 | 1024 | 1272 | 1536 |
At 1080p `flowScale` 2 the top level alone covers a full vector of **256 flow px ≥ 250** (512 px ≥ 500; the requirement is 250 flow px). `flowScale` 1 and 4 give the same 512 px
(n adapts). At 1440p the reach in px is the same as 1080p (the rule is "halve while the short side exceeds 32"): 36% of the height instead of 47%; if that proves short, lower the rule to
"> 24" for 1440p (adds one level at 4K only) — open item, not needed for 1080p. At 4K the reach doubles.
Why exhaustive ±8 at the top: 17 flow px of height leaves a 289-candidate search over the whole level that no candidate list can miss.

## 10. Fallback, scene cut, blur path, UI protection

**Scene cut / fallback** (section 3.12): once per estimate, on the GPU, written to `G.mode`; every synth of the pair reads the same word, so all in-between frames of a pair agree.
- Cut (mode 1): nearer real frame, whole frame. - Failed estimate (`failMix`, soft): `smoothstep(globalFallback, 1.5 · globalFallback, share)`; the flows are mixed toward the camera-model field by that amount and `u` is raised to it; at 1 the in-between frame is a time-weighted blend smeared along the camera motion, whole frame. A ramp, not a switch, so a share hovering at the threshold does not flicker pair by pair.
- Local weak spots never switch to a real frame: they get smear. The only real-frame output is the whole-frame cut, and a blur sample at `t ≤ 0` / `≥ 1` (the real frame, like V2).
- `recordDebugCounters`: `u[0]` = untrusted px, `u[1]` = SAD sum ×256 over `bw·bh` level-0 blocks: unchanged contract.

**Blur path** (`recordSynthBlur`, `blurSamples` ≥ 2): V3 creates no blur pipelines (like V2). `v3Synth` runs `v3_project` with z = `nInt` interior samples (writes `TF[0..nInt−1]`, each
sample exactly what `recordSynth(t_k)` would use) and one `v3_synth` pass that averages all samples in registers (weights even or Gaussian as `blur_resolve.comp`: `exp(−2x²)`, `x = (2k+1−n)/n`),
rounding once. Dispatch count is 2 for any n; blur ring accounting is one set per record (`blurtest.cpp:978`). Scratch: `TF` grows to `nInt` slots (16 B per flow px each: 8.3 MB at 1080p fs 2, 33 MB
at fs 1; n = 16: 133 / 530 MB) by the first blurred record and only grows; failure to allocate returns false. Cheapest correct: it reuses the per-pair estimate and the single-t code path, so each sub-frame
equals `recordSynth(t_k)` to the quantisation (the `blurtest` contract).

**UI protection** (all `uiProtection` modes): Crosshair / WholeScreen: V3's estimate and synth read the clean copies through `takeSet(R_EST/R_SYNTH, estP/estC, …)`, no V3 code. CrosshairV2: the luma fill is seen by V3's Y
(estimate order: static, fill, then planes); the synth calls `uiReject` / `uiRejectC` on every raw tap pair of both hypotheses (`ui_reject.glsl`); `rejectMasks(cb)` binds 11/12 as for V2. After the last synth pass: `uiRecordPatch`
and the two final barriers (`C:2778-2788` pattern). The static-structure mask: S from `v2_static`, E/C from `v3_enclose` (section 3.13); the synth pulls static pixels to the zero-vector blend and the rest of the
clamp/smear leaves them alone (3.15 steps 2, 9). Per-estimate state only; no cross-pair state beyond the existing UI state.

|---|---|

the partner. Symmetric for F10.

## 13. Open risks

1. **Cost.** The estimate is dispatch-overhead-bound (about 27 small dispatches at 5–10 µs) and the synth is the heaviest full-res pass of any version. Levers, in order: drop the ring at level 1, one iteration at levels 3–2 (−0.03), 3×3 dense window (−0.02),
   clamp only the dominant hypothesis (−0.05), smear taps 5 → 3, `v3_enclose` only where S is non-empty (-0.005), fuse `v3_fill` into `v3_occl`, `flowScale` 4 for the flow stages. For 3×/4×: per-t levers are the clamp footprint and skipping the
   static pass when `S` is empty; if 4× must meet 1.1 ms, mode "light" synth (no clamp, 3 smear taps) for t ≠ 0.5 only — a setting would be needed.
2. **Occlusion-edge artefacts** (the earlier V2's failure: hard edges). Mitigations are in the design: soft ramps everywhere, the one-sided weight is `wAc = t(1−o)` (continuous), a vector fill instead of a hold, a little smear where
   `o` is high (`0.25 o_eff`). If artefacts remain: raise `v3OcclSoft`, widen `R_FILL`, add smear at `o`-edges. Never switch to a hard choice.
3. **Fixed-point lookup at motion boundaries.** Two layers through one x, or a hole where nothing lands. The design uses two flows (one of the two usually reaches x), the residual `r` as a hole measure, and the agreement-based soft choice. If the 2-iteration
   fixed point oscillates at a strong edge: 3 iterations, or start from the smaller-|v| hypothesis; if holes show: raise the hole smear (`s` includes `hole`).
4. **Thin fast objects lost at coarse levels, wrong-period lock.** Handled by dominant/camera candidates, the wide search on flagged blocks, and the ambiguity probes feeding `u`. If the probes are too weak for a pattern: add probes at level 0 on flagged blocks;
   the amb weight 0.8 and `v3Smear` are the visible knobs. A trunk thinner than a 4×4 level-1 block that moves differently from its background can still be missed by the block search; the dense pass can recover only what the 4 surrounding block vectors offer.
5. **Camera model is affine only** (no perspective): a strong perspective change (a looming wall) leaves a residual the search must absorb; `G.affValid` rejects bad fits and the candidates simply stop helping.
6. **CrosshairV2 fill does not reach chroma.** The crosshair stays in V3's chroma planes; static zero-vector candidates and the static mask limit the damage. If it shows: zero the chroma window at the fill's boxes (needs the box rectangles; not available to the estimate today).
7. **TF memory for the blur path** at `flowScale` 1 and n = 16 (530 MB). If a device lacks it the record fails cleanly; chunking the samples is a later change.
